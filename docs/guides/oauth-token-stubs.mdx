---
title: "OAuth token stubs for stdio MCP"
description: "Synthetic refresh responses without exposing account credentials."
---

F8 lets a stdio MCP client use normal OAuth refresh logic while the gateway
keeps the real provider tokens. Configure the client with the connected
API-account key returned by [OAuth account sign-in](/guides/oauth-apps):

| Client field | Placeholder |
| --- | --- |
| Refresh token | `av-refresh:<account key>` |
| Access token | `av-access:<account key>` |

This account-specific placeholder convention is the NanoClaw
integration contract; the host must put these values, not real tokens, in the
stdio client's configuration. Neither placeholder is a gateway bearer token.
Mount only the group's scoped proxy socket as usual.

The gateway records token authorities from configured apps and pinned account
metadata in a persistent, instance-wide interception registry. Known authorities
force MITM on CONNECT regardless of the caller's vault, even after disconnect
or app deletion. This intentionally overrides unmatched-host tunnelling.
Clients must trust the gateway CA. Unknown authorities retain normal policy:
the gateway cannot inspect arbitrary blindly tunnelled hosts.

A form-encoded HTTPS POST to the account's exact pinned token endpoint with
`grant_type=refresh_token&refresh_token=av-refresh:<key>` returns synthetic
access/refresh tokens and an expiry. The account must be connected in the
socket's vault and match that endpoint. Unknown, cross-vault, disconnected or
wrong-endpoint placeholders return OAuth `400 invalid_grant`; wrong methods or
malformed grants return `400 invalid_request`. Near-miss paths on known token
authorities do not acquire a valid synthetic refresh response.

The synthetic endpoint does **not** contact the provider, even to refresh.
Actual token refresh happens only when a subsequent API call resolves the
real account credential for injection. Real values never appear in the
synthetic response. Token requests are limited to 64 KiB, responses are
`Cache-Control: no-store`, and request logging records only normal metadata.

Ordinary refresh requests without the placeholder prefix retain their
original body and follow existing proxy/service policy. Stub tokens do not
grant access to a destination not covered by that account's generated
host routes. MCP authorizations retain their separate resource-scoped routing.
