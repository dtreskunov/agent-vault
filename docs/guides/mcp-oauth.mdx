---
title: "Shared MCP OAuth connections"
description: "One resource/client/refresh lifecycle with explicit group bindings."
---

MCP consent belongs to a native managed user's connection, not a receiving
group. The host first provisions that user and library using
[managed gateway setup](/guides/nanoclaw-gateway).

## Create and authorize

```http
POST /v1/managed-users/{user}/connections
Content-Type: application/json

{"label":"Example MCP","kind":"mcp_oauth","resource_url":"https://mcp.example.com/mcp"}
```

The draft has a stable connection ID. Start consent with
`POST /v1/managed-users/{user}/connections/{connection}/oauth/start`, body
`{resource_url?,app_id?,scopes?}`. Resource and explicit app identity are pinned;
use a different connection for a different identity. The result is
`{state,authorize_url}`.

Existing discovery, RFC 7591 dynamic registration, configured apps, client
metadata documents and PKCE are reused. Registrations are connection-scoped,
including multiple accounts at the same resource in the same user's library.
There is no automatic account merge or scope union. An explicit app resolves
ambiguous issuer configurations. MCP services remain resource/path/port scoped.

The authenticated callback relay sends:

```http
POST /v1/oauth/complete
Content-Type: application/json

{"user_id":"<initiating native ID>","state":"<state>","code":"<code>","iss":"<issuer>"}
```

The same authorized host transport is required. The native user must still be
active and own the exact connection. Ownership/revision is checked before and
after token exchange. State is single-use, expires after ten minutes, and pins
resource, issuer, client, redirect, verifier and initiating user. Forward `iss`
unchanged when present; RFC 9207 providers require it. Completion returns
`{connection_id,status,account?,code?,error?}`, never a vault credential key.
Anonymous browser completion cannot complete a managed flow.

Refresh `GET /.../connections/{connection}` and grant the whole connection to a
group vault with PUT `/.../grants/{vault}` and `{}`. Drafts cannot be granted. Tokens,
refresh-token rotation and DCR client state stay central and encrypted. A
`needs_reconnect` connection needs another owner consent, not registration by
the container. Existing agent grants follow the connection's current and future
URL rules and permissions approved by its owner, without separate reapproval.

## SDK placeholders (F8)

Group access metadata/discovery exposes an opaque `BIND_...` credential handle
for an OAuth binding. Configure `av-access:<binding handle>` and
`av-refresh:<binding handle>` in stdio clients, never a connection ID, library
key or real token.

Known token authorities are intercepted persistently, even after disconnection.
Only an active binding in the authenticated group can refresh at the exact
pinned HTTPS token endpoint. The synthetic response returns that binding's
placeholders, never contacts the provider and never exposes real tokens.
Injection performs the central real refresh when needed and rechecks native
authorization after resolution. Revoked, suspended, wrong-endpoint and copied
cross-group handles fail explicitly. Operator-approved unmatched blind tunnels
remain uninspected.

Credentialed streams are rechecked every 100 ms and terminated when authority
is lost. New requests never use a cached positive grant decision. Removing a
group or its final grant leaves the OAuth account and registration intact.
Only owner deletion of the global connection invokes configured revocation and
client cleanup; failures return `502` and retain disabled encrypted state for
an explicit retry. Providers without revocation metadata support local
disconnection only.

Earlier group-owned `/mcp-oauth` routes and automatic startup conversions are
removed. Unsupported populated fork state requires reviewed offline adoption
before listeners or restored sockets start.
