---
title: "Shared static connections"
description: "Store a static credential set once in its native user's library."
---

NanoClaw manages credentials through the authenticated host, never through a
container or group-owned credential CRUD endpoint. See
[managed gateway setup](/guides/nanoclaw-gateway) for native identity provisioning.
All requests below require the authorized `nanoclaw-host` agent and explicitly
select the active mapped native user in the URL. Transport owner privileges are
not inherited by that user.

## Create once

`POST /v1/managed-users/{user}/connections` is create-only:

```json
{
  "label": "Example API",
  "kind": "static",
  "values": {"API_KEY": "<write-only value>"},
  "services": [{
    "name": "example-api",
    "host": "api.example.com/v1/*",
    "auth": {"type": "bearer", "token": "API_KEY"}
  }]
}
```

Values use UPPER_SNAKE_CASE keys. Bearer, Basic pairs, API-key headers, multiple
custom-header templates (`{{ KEY }}`), and scoped substitutions reuse native
broker recipes. Services require explicit names and HTTPS. Each referenced key
must belong to the same connection. Overlapping selected services are rejected,
not resolved by private/shared precedence.

The response contains safe connection metadata, key **names**, services, native
owner, grants, status and an opaque quoted `revision`. It never contains values.
`GET /v1/managed-users/{user}/connections` returns `{connections:[...]}`.
Individual GET uses `/connections/{connection}` and includes `ETag`.

## Rotate or edit

`PUT /v1/managed-users/{user}/connections/{connection}` accepts a subset of
`{label,enabled,services,values}` and requires the exact revision in `If-Match`.
Missing preconditions return `428`; stale revisions return `412`. Reload and ask
the user to review a conflict; never retry as an upsert.

`values` patches named components, including new valid keys. Omitted components
are retained. Rotation is encrypted once and is immediately used by all active
references. Service-policy changes suspend grants until explicitly reapproved.
Disabling a connection suspends use; reenabling does not silently reapprove it.

## Share selected services

```http
PUT /v1/managed-users/{user}/connections/{connection}/grants/{group-vault}
If-None-Match: *
Content-Type: application/json

{"services":["example-api"]}
```

The effective user must both own the connection and hold native destination
vault-admin membership. Instance ownership does not substitute for membership.
An existing grant returns `409` without an exact `If-Match` connection revision.
Updates/reapproval require that exact current revision. Selected names must
belong to the connection; receivers cannot retarget, rotate or reshare it.

Owner detach uses DELETE on the grant URL. Destination admins may instead use
`DELETE /v1/managed-users/{user}/vaults/{vault}/access/{connection}`.
`GET /.../vaults/{vault}/access` returns `{grants:[...]}` with only that group's
connection references, owner labels, approved services and status.

Detachment never deletes the source or invokes upstream cleanup. Global
connection deletion is owner-only and first revokes every recipient. There is
no credential-copy, fan-out synchronization or F12 API.

The fork's earlier `/keys`, `/key-sets` and group-owned connection-management
routes are removed, not aliases. Native upstream standalone credential/service
management remains available outside headless mode.
